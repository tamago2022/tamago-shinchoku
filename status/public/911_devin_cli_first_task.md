# 911番：ログイン後すぐ投げる実案件プロンプト（画像の重さを落とす）

## なぜこれを選んだか
- 正解が数字で出る（ファイルサイズが減る／見た目が変わらない）。見た目・コピー・好みの判断が要らない。
- `joy-relief-station`（q911-0904ワークツリーで実測）で最も重い画像が見つかった：
  - `public/badges/concierge-pick.png` = **2,592KB**（1536×1024、PNG RGBA）。バッジ画像として明らかに過大。
  - `src/assets/egg-concierge-*.png` 系も軒並み600KB〜1.1MB台（rain/summer/chef/rocker/laugh/apology/tuxedo等）。

## 遅い操作を直す5行（既存の憲法テンプレート）
```
遅い操作：バッジ・コンシェルジュ画像の配信（PNGのまま無圧縮で置かれている）
今の待ち時間：concierge-pick.png 2,592KB / egg-concierge-*.png 各600KB〜1.1MB
目標：見た目の劣化なしで concierge-pick.png を500KB以下、理想100KB台。egg-concierge-*も同程度まで
発生条件：該当ページを開くたびに読み込まれる（軽さ＝ごきげん補給所の価値そのもの、という憲法あり）
変えてはいけないもの：解像度・透過・色味・ファイルパス（参照コード側の変更は不要にする＝ファイル名のまま中身だけ差し替え）
```

## Devin CLIへ投げるプロンプト（そのまま `/plan` の入力に使える）

```
joy-relief-station リポジトリの画像を軽くしてください。

対象：
- public/badges/concierge-pick.png（現在2,592KB、1536x1024）
- src/assets/egg-concierge-*.png（現在600KB〜1.1MB程度、複数ファイル）

やること：
1. 各ファイルの現在のサイズ(KB)を計測して記録する
2. 見た目（解像度・透過・色）を変えずにファイルサイズだけ圧縮する
   （pngquant / oxipng 等の可逆圧縮、またはWebPへの変換＋既存参照の更新のどちらでもよいが、
    ファイルパスを変える場合は参照している全箇所を追従修正すること）
3. 圧縮後のサイズを計測し、圧縮前後を表にする
4. npm run build が通ることを確認する
5. 変更をコミットしてPRを作る

正解条件（機械で判定できる）：
- 全対象ファイルの合計サイズが50%以上削減されている
- npm run build が exit 0
- 画像を開いたときに視覚的な破綻（透過が消える等）が無いこと
```
