## 1. CSV一括ダウンロードの実ファイルURL

`https://rssystem.go.jp/download-csv` はJS描画（Vite/React製SPA）で、年度選択・ダウンロードボタンはすべて`<button>`でJSが動的にURLを組み立てる方式。`<a href>`には直リンクが出ない。

- 年度別ページ: `https://rssystem.go.jp/download-csv/2024`
- 「5-1_支出先_支出情報」ZIPボタンをクリックした際の実際の取得先URL（`performance.getEntriesByType('resource')`で捕捉）:
  ```
  https://rssystem.go.jp/files/2024/rs/5-1_RS_2024_%E6%94%AF%E5%87%BA%E5%85%88_%E6%94%AF%E5%87%BA%E6%83%85%E5%A0%B1.zip
  ```
  （= `.../files/2024/rs/5-1_RS_2024_支出先_支出情報.zip`）
- URL規則: `https://rssystem.go.jp/files/{年度}/rs/{番号}_RS_{年度}_{カテゴリ}_{ファイル名}.zip`（推定。他11ファイルも同一パターンと思われるが、実クリック確認は5-1のみ）
- 配信元: AmazonS3 + CloudFront（認証なし、直接GETで200が返る静的配信）

## 2. ファイル形式の実測（★実際にダウンロード＝fetchしてバイト列を検証済み。URLが分かっただけではない）

上記ZIP URLに対しブラウザのJS `fetch()` で実際にGETし、レスポンスをBlobとして受信・検証した（`content-length: 5,920,574 bytes` を実受信、ステータス200、`content-type: application/zip`）。さらにZIPのセントラルディレクトリをJSで自前パースし、中のCSVエントリをDeflate展開して先頭約64KBの実データを読み取った。

| 項目 | 実測結果 |
|---|---|
| 形式 | ZIP（1ファイルのみ内包） |
| 内包CSVファイル名 | `5-1_RS_2024_支出先_支出情報.csv` |

## 4. 判断メモ（たまごさんへの確認なしで自分で決めた点）

- CSV一括ダウンロードの12ファイル全部ではなく「5-1_支出先_支出情報」1本のみ実クリックで検証した。理由：同一UI・同一URL規則で、1本の実測で「引ける」ことの証明としては十分と判断したため。
- 65MBのCSVを全行パースはしていない（先頭約64KB分のみ）。行数の厳密カウントは試作段階では不要と判断し省略。
- 特別会計名は事業ページに「エネルギー対策特別会計」という完全名では書かれておらず、「会計：エネルギー対策／勘定：電源開発促進勘定」という表記だったため、そのまま原文表記で記載した（正式名称への言い換えはしていない）。
- 支出先データはCSV一括ダウンロード（5-1ファイル）からではなく、事業個別ページ（同一のRSシステムの一次資料）から取得した。理由：65MB全体をブラウザ上で全展開・grepするのは試作としては過剰で、個別事業ページの方が同じ情報に軽く到達できるため。
