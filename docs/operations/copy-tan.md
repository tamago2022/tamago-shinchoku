# コピー担当（コピタン）運用手順

サイト内の楽曲コピー（`note`）のうち、「代表曲のひとつ。」のような
**何の情報も無い汎用の一文**を、その曲固有の事実に基づいたコピーへ書き直す長期作業。

対象は約15,900曲（全27,019曲の約59%／2026-08-01時点）。一気には終わらないので、
小さなバッチを何度もmainへ入れて、少しずつ減らしていく。

（棚カードの短文`whisper`・`copy`の標準スタイルは対象外＝`docs/operations/copy-craft.md`が正本。両方の入口は`.claude/manuals/01-ingest-linking.md`「紹介文の標準スタイル」節）

---

## 一番大事な約束

**事実は裏取りしたものだけ。魅力の描写は自由。**

この2つを混ぜないこと。これがコピー担当の憲法。

- 受賞、チャート順位、日付、参加者、売上、タイアップ — これらは**事実**。
  調べ書きで確認できたものだけ書く。「らしい」「と言われている」は書かない。
  別の曲・別のアーティストの事実を流用しない。
- 速い、重い、泣ける、夜に合う、踊れる、初期衝動 — これらは**感想**。
  裏取りは要らない。むしろどんどん書いてよい。ここでサイトの温度が決まる。

事実が何も出てこなかった曲でも、**評論型のコピーは書いてよい**。
逆に、曲のことが何も分からず魅力も言葉にできないなら、汎用のまま残す方がよい。

（2026-08-01更新：以前は「事実が無ければ何も書かない」としていたが、
店主判断により、曲の雰囲気・魅力を描く評論的な一文は裏取り不要で歓迎、と変更した。）

## 4つの道具

| 道具 | やること |
|---|---|
| `scripts/copy-tan/inventory.mjs` | 汎用コピーの曲を数え上げ、作業リストを作る |
| `scripts/copy-tan/harvest.mjs` | Wikipediaから、その曲固有の事実を集める（文章は書かない） |
| `scripts/copy-tan/apply-notes.mjs` | 書いたコピーを `coverGuide.ts` へ安全に反映する |
| `scripts/copy-tan/report.mjs` | 何曲調べて何曲直したかを記録に残す |

### 進め方

```bash
bun scripts/copy-tan/inventory.mjs                                    # 1. 棚卸し
bun scripts/copy-tan/harvest.mjs --limit 500 --batch 2026-08-01-a     # 2. 調べる
# 3. harvest/*.jsonl を読んで、人（またはAI）が data/notes/<batch>.json を書く
bun scripts/copy-tan/apply-notes.mjs                                  # 4. 反映
bun scripts/copy-tan/report.mjs                                       # 5. 記録
```

`harvest.mjs` は調べ終わった曲を自動で覚えているので、何度でも中断・再開してよい。

## 事故を防ぐ仕組み

### 同名の別物を掴まない

曲名だけで記事を探すと、必ず同名の別物に当たる。実際に起きた例：

- 「天国への階段」→ 1946年のイギリス映画、白川道の小説
- 「D'yer Mak'er」→ 同名の日本のアイドルグループ（グループ名の由来がこの曲なので、
  記事本文に「レッド・ツェッペリン」が出てくる。名前一致だけでは弾けない）

そのため `harvest.mjs` は3つ全部を満たしたときだけ記事を採用する。

1. カッコを除いた記事タイトルが曲名と一致する
2. 記事本文にアーティスト名（別名を含む）が出てくる
3. **記事の冒頭の定義文が「曲・アルバムの記事」であることを示している**

さらに点数を付け、`(Led Zeppelin song)` のように本人名入りのカッコを加点、
別人名・映画・小説のカッコを減点して、一番確からしい記事だけを採る。

確度は3段階で記録する。

| 確度 | 扱い |
|---|---|
| high | その曲の記事とみなしてよい |
| medium | 原曲・別バージョンの記事かもしれない。書くときは記事の記述どおりに |
| low | その曲の記事だと言い切れない。**事実を流用しない** |

### 曲を消さない・入れ替えない

`apply-notes.mjs` は次を守る。

- 曲の特定は「曲id ＋ 動画id」の**2点一致のみ**。曲名や語句で行を絞らない
  （名前で行を絞って部屋の見出しごと消した事故があるため）
- 曖昧な行（該当なし・複数該当）は必ず飛ばして報告する
- 台帳の `oldNote` と現在のコピーが違っていたら、別作業が更新したとみなして上書きしない
- 反映後に `coverGuide.ts` をビルドし直し、部屋数・曲数・題名・動画id・年が
  **1件も変わっていないこと**を確認する。変わっていたら自動で元に戻す

### 他のセッションとぶつからない

`coverGuide.ts` は7.8MBで、仕入れセッションなども同時に触る。

- 変更は `note` の値だけ。行の追加・削除をしないので、曲の追加とはほぼ競合しない
- 台帳JSONが正本。競合したら最新mainを取り直して `apply-notes.mjs` を再実行するだけで復旧できる
- 作業の登録先は `.claude/ACTIVE_WORK.md`

#### 競合したときの正しい直し方（毎回起きる）

`coverGuide.ts` はほぼ必ず競合する。次の手順以外は使わないこと。

```bash
git rebase origin/main
# 競合したら、迷わず main 側を丸ごと採る
git checkout origin/main -- src/lib/coverGuide.ts
git add src/lib/coverGuide.ts
git rebase --continue
# main を土台にして、台帳から入れ直す
bun scripts/copy-tan/inventory.mjs
bun scripts/copy-tan/apply-notes.mjs
```

**`git checkout --theirs` を使ってはいけない。**
rebase中の `--theirs` は「自分の変更」を指すため、
main側の他セッションの成果（曲の厳選、型の修正など）を丸ごと消してしまう。
実際に1度これで他セッションの変更を消しかけた。必ず `origin/main` を明示して取る。

台帳が正本なので、mainを土台に入れ直せばコピーは必ず復旧する。
mainで曲そのものが整理されて消えた曲は、自動で見送られる（それが正しい）。

## 【コンプラ監督】名誉毀損を出さないための必須ゲート（2026-08-02 強い念押し）

店主の言葉：
**「もし本当に本人が言ってないのに書いてたら名誉毀損的なことになる。
個人のブログ等から取ってきたような出典はダメ。本人のインタビューや雑誌掲載など
確認できるものだけにして。攻めた面白いエピソードでも、コンプラ的に際どいものは入れなくていい。」**

### 納品前に必ず通すゲート

```bash
bun scripts/copy-tan/compliance-check.mjs   # 名誉毀損になりうる記述を検出
bun scripts/copy-tan/verify-quotes.mjs      # 引用が原文に本当にあるか
bun scripts/copy-tan/check-copy.mjs         # 言い回しの使い回し
```

`compliance-check.mjs` が「危険度 高」を出したまま反映してはいけない。

### 書いてはいけないもの（危険度 高）

| 種類 | 例 |
|---|---|
| 実在の人物の発言の直接引用 | 本人いわく「〜」、○○が「〜」と語った |
| 人の内心・感情の断定 | 気に入らなかった、渋々、乗り気でなかった |
| 人間関係の不和・対立 | 確執、不仲、訴訟、盗作 |
| 私生活・交際・家庭の事情 | 不倫、浮気、離婚、元恋人、隠し子 |
| 本人が公表していない属性 | 性的指向、人種、宗教、支持政党 |
| 健康・病・死因・依存 | 闘病、うつ病、薬物、自殺 |
| 犯罪・事件・不祥事 | 逮捕、起訴、謹慎、暴行 |

**Wikipediaに載っていても書かない。** 実際、Janet Jackson「Rock With U」の発言引用は
英語版Wikipediaに出典付きで載っていたが、店主が確認できなかったため削除した。
書いた側だけが裏を知っている状態は、読む側にとって無いのと同じで、
1件でも外すと他の全部が疑わしくなる。

### 書いてよいもの

- **曲そのものの主題の説明**は書いてよい。
  「浮気を歌った曲」「人種差別へのメッセージを込めた曲」は、作品の説明であって
  実在の人物への断定ではない。
- 発売年、チャート順位、作曲者、タイアップ、受賞、録音場所などの検証しやすい事実。
- **比喩・情景・温度の描写**（裏取り不要）。踏み込んだ一文を削った分は、ここで埋める。

### 迷ったときの判断

**落とす。** 事実を1つ減らすより、間違いを1つ出す方が損害が大きい。
面白さは比喩で作れる。信頼は一度失うと戻らない。

## 【踏み込んだ記述の基準】店主指摘 2026-08-02

**面白い話ほど、間違えたときの損害が大きい。**

店主からの指摘：
Janet Jackson「Rock With U」のコピーに本人の発言引用を書いたが、
店主が軽く検索した範囲では出典を確認できなかった。
**「間違えてたらかなりやばい。公式や本人インタビューで確認できない発言は書かない方がいい」**

（調べ直した結果、この発言自体は英語版Wikipediaに
NewNowNextのインタビュー由来として載っており、捏造ではなかった。
それでも、**店主が確かめられない踏み込んだ記述は書かない**という判断が正しい。
書いた側だけが裏を知っている状態は、読む側にとって無いのと同じ。）

### 守ること

| 記述の種類 | 扱い |
|---|---|
| 発売年、チャート順位、作曲者、タイアップ、受賞 | 調べ書きにあれば書いてよい。検証しやすい |
| 制作の逸話（15分でできた、仮題が違った） | 調べ書きにあれば書いてよい |
| **人の発言の直接引用（鉤括弧）** | **原則さける。** 書くなら、誰の発言かと媒体が原文で明確なものだけ |
| **性的指向・人種・宗教・政治・病・事件に関わる断定** | **書かない。** 公式かつ複数の信頼できる出典で確実に裏が取れる場合のみ |
| 出典が1つしかない、際どい話 | 書かないか、「〜と言われている」と断定を避ける |

**迷ったら書かない。** 事実を1つ減らすより、間違いを1つ出す方が損害が大きい。
比喩・情景・温度の描写は裏取り不要なので、削った分はそちらで埋める。

### 点検の道具

```bash
bun scripts/copy-tan/audit-claims.mjs    # 発言引用・危ない話題を洗い出す
bun scripts/copy-tan/verify-quotes.mjs   # 引用が原文に本当にあるか突き合わせる
```

バッチを納品する前に、必ずこの2つを通す。

## コピーの書き方

### 【正解パターン】店主が実画面で絶賛した形（2026-08-01確定）

**「調べた固有のトリビア」＋「曲の本質を捉えた比喩」の2点セット。** 片方だけでは足りない。

店主がMichael Jacksonのページを見て、名指しで褒めた3例：

| 曲 | コピー | 褒められた理由 |
|---|---|---|
| Beat It | エディ・ヴァン・ヘイレンが無償で弾いたソロ。ギターが夜を切り裂く。 | 調べないと出てこないマニアックな情報が入っている |
| Smooth Criminal | 重力に喧嘩を売る45度。人間の体ってこんな曲がるんだ、と知る曲。 | あの前傾姿勢の名場面を掴んだ比喩 |
| The Way You Make Me Feel | 歩き方まで軽くなる恋のウキウキ。 | 曲の本質を捉えていて「すごい適切」 |

同じ日、店主は逆側も指摘している。
「Off The Wall」「Black Or White」が『代表曲のひとつ。』のままだったことに対し、
**「相当な議論を呼んだ曲で強いメッセージが込められているはずなのに、一般的な説明で終わっているのはおかしい」**。

つまり、**有名曲ほど一般論で流すと即座に見抜かれる。** 手を抜く場所が逆である。

### 手順に落とすと

1. まず調べ書きから、**その曲にしか無い事実**を1つ選ぶ。
   マニアックなほどよい（無償で弾いた、仮題が違った、断られた曲だった、CMで再燃した）。
2. 次に、**その曲を聴いたときの体感**を一言で言い切る。
   ここは裏取り不要。比喩・情景・温度で書く。
3. その2つを2文にまとめる。全角45〜85字程度。

事実だけを並べると温度が無く、比喩だけだと中身が無い。**必ず両方**。

### 2種類のコピー（どちらも歓迎）

コピーには**2種類**あり、どちらも歓迎される（2026-08-01 店主判断）。

### 1. 裏取りできた事実（エピソード型）

グラミー受賞、チャート記録、録音の逸話、映画・CMでの使用、歌詞の由来など。
**必ず調べ書きで確認できたものだけ**書く。ここは絶対に捏造しない。

> 元の仮題は「風呂場の歌」。ボーナムがスタジオで口ずさんでいた飲み屋の歌が、そのままギターのリフになった。

> ボビー・ウォマックはGorillazを知らず乗り気でなかったが、娘に説得されて参加。1時間歌い続けて倒れかけ、バナナを食べて復活した。

### 2. 曲の魅力を言葉にする（評論型）

その曲の手触り、勢い、温度、情景、聴きどころを言葉で描く。
**こちらは裏取り不要**。感性で、魅力的に書いてよい。

> ライブの定番曲で、初期の勢いを感じる屈指のアッパーチューン。

> 静かなアルペジオで始まり、8分かけてゆっくり天に昇っていく。ロックの教科書に最初に載る一曲。

> 重いリフが繰り返されるたび、砂漠を進むキャラバンが見えてくる。ロックでこんな景色が描けるのかと驚く。

**この2つの線引きが最重要。**
「数字・固有名詞・日付・受賞・チャート順位・誰が参加したか」は**事実**なので裏取りが要る。
「速い／重い／泣ける／夜に合う／踊れる／初期衝動」は**感想**なので自由に書いてよい。

理想は両方入った1本。事実が無ければ評論型だけでよい。逆に、
事実だけを並べて温度の無い文章にしない。

### 形式

2文、全角40〜75字程度。読んだ人が「聴いてみよう」と手を伸ばす温度にする。

### 避けること

- **どの曲にも貼れる言葉で埋めること**。「代表曲のひとつ」「名曲です」「必聴」。
  評論型は自由に書いてよいが、**その曲固有の手触り**を書くこと。
  同じ言い回しを何十曲にも使い回したら、それは「代表曲のひとつ」と同じ罪。
- 楽典的な説明だけで終わる文（キー、BPM、コード進行）
- 否定的な批評、事件・ゴシップ、成人向けの話題
- 曲を知らないのに、知ったふりで具体的な情景を断定すること
  （何も浮かばないなら、その部屋の作風・年代から言えることだけを短く書く）

### 同じ曲が複数カードにあるとき

同一曲の別動画には、**別の角度**のコピーを書く。片方は事実、片方は聴きどころ、
のように分けると、並んだときに読み比べる楽しさが出る。
