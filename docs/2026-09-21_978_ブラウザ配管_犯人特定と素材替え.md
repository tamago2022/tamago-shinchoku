## 1. 結論（先に）

**タブは消えていない。消えているのは claude-in-chrome 拡張の「タブグループ登録」だけで、タブ本体はChromeに残って孤児になる。**
そしてそれを起こしているのは **Macの資源枯渇**。Chromeは生きているのに、拡張のUI層（`chrome.tabGroups`）の状態が保持できていない。

これは**新しい不具合ではなく、再発**。たまごさん自身の `status/failures.md #22`（2026-09-09・704番）に
同じ症状・同じ原因・回避策（生CDP）が実機検証つきで既に書いてある。

「25秒」という寿命は正体ではない。**今日は0秒で死んだ（5回中5回）。**
Chromeが応答できるかどうかの揺らぎが、たまたま25秒付近に見えていただけ。

## 3. 替える案（修理ではなく素材替え）

### 案1 ★本命：本体Chromeを「生CDP」で叩く。拡張のタブグループを通らない。 — **¥0**

- **何をする**：本体Chromeを `--remote-debugging-port=9222`（127.0.0.1限定）付きで立ち上げ直し、
  ブラウザ工程を `~/.tamago/browser_peek.mjs` 方式（`chromium.connectOverCDP()` ＋
  `Target.createTarget({url, background:true, newWindow:false})`）へ移す。
- **何が要るか**：起動スクリプト（launchd plist）1枚と、`browser_peek.mjs` の接続先ポートを9222にする1行。
  **playwright-core 1.62.1 は `~/.tamago/node_modules` に導入済み**（実測）。`browser_peek.mjs`（7,205バイト）も存在。
- **いくら**：**¥0**
- **たまごさんの手**：**一度だけ「Chromeを終了していい」の一言だけ。**（開いていたタブは再起動で復元される）
- **効く範囲**：Genspark・Lovable・Devin・請求画面、**全部**。ログインは今のプロファイルのままなので使える。
- **なぜ効くと言えるか**：`failures.md #22` に「`windowState:"minimized"` のままでも新規タブ作成・goto・
  タイトル取得・スクリーンショットが成功」「`Target.createTarget(background:true)` は5回連続で
  windowStateが一度も変化しない」という**実機検証済みの記録**がある。拡張のUI層を一切通らない。
- **今できない理由**：本体Chromeの起動引数に `--remote-debugging-port` が**無い**（実測。9220〜9229 に listen 無し）。

### 案2：既にある「公開専用Chrome」（別プロファイル・CDP 9223）を常駐させて、そちらへ逃がす — **¥0**

- **何をする**：`~/Library/LaunchAgents/com.tamago.joy-relief-station.lovable-publish.plist`（**既にファイルは有る**）を
  load し直して、`~/.tamago/chrome-publish` プロファイルのChromeをCDP 9223で常駐させる。
- **何が要るか**：`launchctl load` 1回。素材は全部揃っている（プロファイルの Cookies も 09-19 付けで残っている）。
- **いくら**：**¥0**
- **たまごさんの手**：**不要**。
- **弱点**：**別プロファイルなのでGenspark/Devinのログインが無い。** 今いちばん困っている所には効かない。
  ログイン不要な工程（公開ページの実測・見た目確認）を逃がして本体Chromeの負荷を下げる用。
- **今できていない理由**：`launchctl list` に載っておらず、9223 は無応答（実測）。

### 案3：原因の側を replace ——「同時2本」を機械で強制する — **¥0**

- **何をする**：今8本走っているClaudeセッションを、決まり通り2本に機械で抑える。
  13時間ストールしている pid 99564 を落とす。`machine.json` は既に `cap:2` と判定しているのに実際は8本。
- **何が要るか**：既存の `machine_health.py --reap` の判定を「超過分は実際に落とす」まで通すだけ。
- **いくら**：**¥0**
- **たまごさんの手**：**不要**。
- **効き方**：ブラウザだけでなく全工程が速くなる。ただしブラウザの死因（拡張のタブグループ）そのものは消えないので、**案1と一緒でないと完治しない。**
- **参考（たまごさんの手が要る側）**：Brave 12.6GB / 58プロセスを閉じるのが一番効く。ただしこれはたまごさんの領分なので触らない。

## 4. 孤児タブが溜まらない仕組み（作った・実測済み）

**「最後にまとめて閉じる」は使えない。**上の2-1のとおり、拡張は閉じる相手を見失っている。
セッションが自分で閉じる方式は、**原理的に間に合わない。**

### 予約閉栓（デッドマン方式）

タブを**開く前に**「この票の心拍が止まったら、このURLのタブを閉じてよい」と
外側（Mac上で回り続ける工場）へ**先に**預けておく。セッションが落ちたら心拍が止まり、工場が閉じる。
**セッションの生死に依存しない。**

- 新規：`tools/chrome_reserve.py`
  - `take --id <番号> --url <URL> --ttl 120` … 開く前に票を置く
  - `beat --id <番号>` … 心拍（生きている間だけ打つ）
  - `release --id <番号>` … 自分で閉じられたら票を捨てる
  - 票は `status/chrome_reserve/*.json`（`status/*` は .gitignore 済み＝公開リポに入らない）
- 改修：`tools/chrome_tab_sweeper.py`
  - 期限切れの票に載ったURLを閉じる（`pick_reserved`）
  - 期限切れの票が1枚でもあれば **15分の間引きを自分で外す**（`gate_ok`）
  - **osascriptの口は増やしていない。**既存の掃除機に相乗りしただけ（Macをこれ以上重くしない）

### 安全側（掃除機の憲法をそのまま継承）

1. 前面タブ（active）は何があっても閉じない
2. ウィンドウの最後の1枚は閉じない（`SKIP_LAST`）
3. **たまごさんが一度でも前面に出したURLは閉じない**（`chrome_tab_history.json` の `everActive`）
4. 票に書いた枚数までしか閉じない（同じURLをたまごさんも開いていたら巻き添えにしない）
5. 閉じる直前に、そのindexのURLが票と一致するか確認する（`SKIP_MOVED`）

### 叩いて確かめたもの（978d / 978e / 978f）

| 確かめたこと | 返り |
|---|---|
| import が通り、掃除機が票を読める | `import OK / _reserve= True` |
| 票が無いときは何もしない | `{"tickets":0,"expiredUrls":0}` |
| 期限切れの票を検出する | `{"tickets":1,"expiredUrls":1,"urls":["..."]}` |
| **心拍を打つと期限切れが消える（＝生きているセッションは守られる）** | `{"tickets":1,"expiredUrls":0}` |
| 実際に孤児を閉じられる | 09:33:28 `seen:19 candidates:5 **closed:4**`（私が作った newtab 4枚。たまごさんのタブは0枚） |

**未検証**：「票に載ったURLを票の力だけで閉じる」最後の一歩は、09:37以降 Chrome が
`windows 0 / tabs 0` を返すようになったため今日は実地で踏めていない。判定までは4/4で通っている。
