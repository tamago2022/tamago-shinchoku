## ★3. 本当の原因 ― 関所に門が1つ足りなかった

14曲が3日間止まっていたのは、動画idが無かったからではない。

> **関所が「PASS」と言ったのに、棚に出せなかった。**
> しかも止まっていた場所が `status/nyuka/done/`＝**誰も見ない暗がり**だった。

**札は「押したら鳴る」までが1枚。鳴らない札は札ではない。**
なのに関所は、鳴るかどうかを一度も見ていなかった。1曲ずつ拾う話ではない。**門が足りない。**

### 足した門0（棚に出せるか）

`tools/nyuka_sekisho.py` に門0を新設した。**門1より前＝採点にお金を使う前に落とす。**

| | |
|---|---|
| 動画idが無い | **通さない**（hold/ へ理由つきで落ちる。pending/ にも積ませない） |
| 動画のURLしか無い | URLから11文字のidを**機械で取り出して埋める** |
| idの形が違う（11文字でない） | 通さない |
| ★動画を探しに行く | **やらない。**探した結果が正しい保証が無い（関所の掟）。人が確かめて入れるまでが仕入れ |

### 再発したら機械が落ちる

`python3 tools/nyuka_sekisho.py --selftest` に**見本3問**を足した。
**3問とも、実際に3日間止まっていた14曲そのものの形**（作った例は0）。**既存9問と合わせて全問合格。**

### 暗がりを無くした

`--shelf-check` を新設し、5分便に相乗りさせた（**新しい常駐は増やしていない**・14ファイル読むだけ）。
`status/public/nyuka_shelf.json` に「通ったのに棚へ出せない数」が出る＝**進捗表から見える。**
いまの数は **1曲**（akiko）。
