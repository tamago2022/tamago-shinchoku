# ログインの口を1本にした（1161番の続き）2026-09-27

## 何が起きていたか（実測。憶測ではない）

`claude` の起動が `Failed to authenticate: OAuth session expired and could not be refreshed` で落ちた。
しかし鍵の側は生きていた：

```
~/.tamago/claude_token          len=108（sk-ant-oat01-…）
~/.tamago/claude_token.minted   2026-09-26 13:48:09 ＝ 期限 2027-09-26（残り363日）
~/.tamago/use_token             立っている
~/.claude/.credentials.json     存在しない
```

つまり**鍵は在って合図も立っているのに、その呼び出しには鍵が渡っていなかった。**
`OAuth session expired` はキーチェーン側の短命OAuthが出す文言で、
1年もつ鍵（`CLAUDE_CODE_OAUTH_TOKEN`）を渡した呼び出しは絶対にこの文言を出さない
（渡した鍵が死んでいるときは `401 OAuth access token is invalid` になる。2026-09-26 の実測）。

鍵を渡す正本は `tools/claude_auth.py` の `claude_env()` だが、
それを通さずに `~/.local/bin/claude` を直に叩く口が1本でも残れば、**その口だけが今日と同じ形で落ちる。**
＝呼ぶ側を全部直す作戦は、必ず1本忘れる。

## 直した3か所（穴に段ボールを貼らず、パイプを替えた）

### 1. `~/.local/bin/claude` そのものを「鍵を入れてから本体へ渡す包み」にした
実物 `tools/claude_kuchi_install.py`。以後**どの口から叩いても**鍵が入る。

- `setup-token` / `login` / `logout` のときは入れない（作り直しの邪魔をしない）
- 呼ぶ側が既に鍵を渡しているときは触らない
- 合図（`use_token`）が無いときは何もしない＝今までどおり
- 本体の在り処は `~/.tamago/claude_real` に控える
- 張った直後に `claude --version` を**実測**し、通らなければ自分で元のシンボリックリンクへ戻す
- claudeの自動更新で包みが消えても、5分便が毎回張り直す（自己修復）

実測：`2.1.278 (Claude Code)` が包み越しに返った。

### 2. 見張り（auth_keeper）を関所に並ばせるのをやめた
実測：09-27 07:52〜14:35 の probe **10回が全部**「混んでいて測れなかった」。
1158番の関所が同時上限1本なので、本物の発車が枠を持っている間、見張りは待つだけで
120秒に間に合わない。＝**7時間、ログインの生死を誰も測っていなかった。**
「切れたら即わかる」が、工場が動いているときだけ効かない逆立ちした作り（1161番の再発）。

関所の目的は、同時起動が refreshToken を作り替えるときの取り合いを止めること。
`CLAUDE_CODE_OAUTH_TOKEN` を渡す形は**作り替えが一切起きない**ので、並ぶ理由が無い。
→ トークンで測るときだけ関所を通さない（キーチェーン側で測るときは今までどおり通す）。

### 3. 鍵を取り直している最中に、5分便が後ろから撃つのをやめた
`tools/machine_status_push.sh` は5分おきに `pkill -f "claude setup-token"` していた。
1161番の取り直しは `setup-token` を最大25分走らせる。
＝**取り直しそのものを5分おきに撃っていた。**「取り直しが1回で終わらない」の正体。
→ `status/1161_toru.lock` がある間は撃たない（30分以上古いロックは事故なので今までどおり撃つ）。

## 切れる前に自分で巻き直す（新設）

実物 `tools/kagi_jidou_makinaoshi.py`。5分便に相乗りし、中で1時間ゲートする。

- 残り日数を `status/public/kagi_kigen.json` に出す
- 残り**30日**を切ったら、言われる前に 1161番の取り直しを裏で起こす
  （`status/1161_url.txt` にURLが出た状態＝**承認を1回押すだけ**まで自分で進む）
- 鍵が無い／形が違う（80桁折り返しの尻切れ）ときも同じ道で起こす
- 鍵の中身は読まない。`use_token` は立てない（それは「1本通った」を見た係の仕事）

## 進捗表

`login.tokenDaysLeft` / `tokenExpiresAt` を毎回作り直す（auth_keeper の写しに頼らない。
あちらは通った回にしか書かないので、測れない日が続くと古い数字が貼り付く）。
画面には `#loginKigen` の**小さい1行**で「ログインの鍵　あと363日（2027-09-26まで）」。
赤にも黄色にもしない。巻き直し中は同じ行に「承認を1回押すだけ」と出る。
