# Xのサムネイルが出たり出なかったりする件 — 実測と直し方

実測日: 2026-09-19 / 対象: https://joy-relief-station.lovable.app/
調べ方: サーバーが返す生のページを直接取得（ブラウザは使っていない）

---

## 1. 結論

**サムネイルの指定（og:image）は、全ページちゃんと入っていた。足りないのはそこではない。**

「Reactの1枚ものだからクローラーが読めない」という疑いは、**外れ**。
このサイトはサーバー側でページを組み立てて返している。サムネイルの指定も、
検索エンジンやXが読む生のページの中に、最初から入っている。16ページ測って16ページとも入っていた。

**出ない原因は2つ。**

### 原因A：ページが返ってくるのが遅すぎる回がある（これが本命）

16回取りに行って、**3回、3分待っても返ってこなかった。**

| ページ | 結果 |
|---|---|
| トップ `/` | 3分待っても返らず（2回とも） |
| `/room/card/maru-cat` | 3分待っても返らず |
| 他13ページ | 数秒〜十数秒で返った |

Xがサムネイルを取りに来るときの待ち時間は**数秒**しかない。
そこを過ぎると、Xは「このページは無い」と同じ扱いにして、**何も出さずに諦める。**

同じページでも、返る回と返らない回がある。
だから「たまに出る／たまに出ない」になる。**貼った時刻の運。**

### 原因B：サムネイルの画像を、よその倉庫から借りている個体がある

サムネイルの画像の置き場所が、ページによって4種類にバラけていた。

| 置き場所 | 使われているページ | Xで出るか |
|---|---|---|
| 自分のサーバー `/api/public/share-image/…` | 曲ページ・棚・扉・特集 など大半 | 出る（ただし原因Aの遅さを受ける） |
| **X（Twitter）の倉庫** `pbs.twimg.com/amplify_video_thumb/…` | X由来の動画カード（子犬・コンドル など） | **危ない。**この住所は時間が経つと消える。消えたら何も出ない |
| **YouTubeの倉庫** `img.youtube.com/…/hqdefault.jpg` | 一部のカード（アイスの赤ちゃん など） | **小さい。**実物は480×360しかないのに1200×630と書いてある。Xでは大きい絵にならず、小さい四角になる |
| 共通の扉の絵 `og-four-doors.png` | トップ・検索・/en・診断・一部の曲（君が代など） | 出る。ただし**どの曲を貼っても同じ絵**になる |

## 3. 直し方（案を並べた上で、1つ選んだ）

### 並べた案

1. 貼るときにX側へ画像を直接くっつける（リンクのサムネに頼らない）
2. クローラーにだけ、軽いページを即返す層を前に置く
3. ページごとのサムネ指定を、作る時点で静的に焼いておく
4. 事前に全ページを作り置きする（プリレンダリング）
5. サムネ画像を全部いったん自分のサーバーに取り込んで、よその倉庫への依存をやめる
6. 貼る前に機械で点検して、出ないURLは貼らない

### 選んだのは「2 → 5 → 6」の順で入れる

**2（クローラーにだけ軽いページを返す）を本命にする。**
理由：原因Aの「遅くて返ってこない」を根元から消せるのはこれだけ。
1〜数KBの、タイトルとサムネの指定だけが入った紙切れを即返す。
中身を組み立てないので、遅いも速いも無くなる。人間には今まで通りのページを返す。

**5 は同時に入れる。** よその倉庫（Xの `pbs.twimg.com` / YouTubeの `img.youtube.com`）を
やめて、全部 `/api/public/share-image/…` に寄せる。
サイズも1200×630以上に揃える。480×360のままだと、Xでは小さい四角にしかならない。

**6 は保険。** 直したあとも、貼る前に必ず機械で見る（下の点検ボタン）。

**1（画像を直接くっつける）は今日から使える応急処置。**
直るまでの間は、リンクだけの投稿をやめて、画像を1枚付けて出す。これは100%出る。

**3・4 を選ばなかった理由：** どちらも「ページを作る時点で焼く」やり方で、
このサイトは中身がデータベースから来るので、焼いた後に足した曲が出なくなる。

## 4. 渡すときの指示（Devin向け・そのまま渡せる）

対象リポジトリ：`joy-relief-station`（この作業フォルダには無いので、ここからは触れない）

1. クローラー（Twitterbot / facebookexternalhit / Slackbot / LINE / Discordbot など）からの
   アクセスのときだけ、`<head>` だけの軽いHTMLを即返す層を入れる。
   中身：`og:title` `og:description` `og:image` `og:image:width/height` `og:url`
   `twitter:card=summary_large_image` `twitter:image`。本文は空でよい。
   **応答は1秒以内を目標にする。**
2. `og:image` から `pbs.twimg.com` と `img.youtube.com` を無くす。
   全部 `/api/public/share-image/<id>` 経由に寄せ、**1200×630以上**で返す。
   申告する `og:image:width/height` と実物の大きさを一致させる。
3. `/api/public/share-image/…` に長めのキャッシュ指定を付け、2回目以降は即返るようにする。
4. 直したら、下の点検を全URLで流し、**3秒以内に返る＋画像が200で返る**を全件で確認する。

## 5. 貼る前の点検（押すだけ）

`tools/サムネ点検_押すだけ.command` をダブルクリックすると、
URLを1つずつ見て「今なら出る／まだ出ない」の一覧を出す。
点検したいURLは、同じフォルダの `tools/点検するURL.txt` に1行ずつ書く。
