# 2026-09-19 申し送り｜GitHubの見張り番（たまごさんが言わなくても拾う）

## 何を作ったか

joy-relief-station に Issue・コメント・PR が置かれたら、たまごさんが何も言わなくても
工場が自分で拾って発車待ちへ積む。着火は auto_launcher がやる＝人は押さない。通知も出さない。

## 方法を5つ並べて、③を選んだ

| 手 | 見回りの重さ | 気づくまで | 採否 |
|---|---|---|---|
| ① Webhook | 0 | 数秒 | ✕ 公開の受け口が要る。中継所は何度も死んでおり、死んだ間の通知は再送されず消える |
| ② Actions の on: issues | 0 | 数秒 | ✕ 無料枠が尽きている。枠が戻っても工場のMacへ届ける経路は別途必要（①と同じ問題） |
| ③ 条件付きポーリング（ETag） | **ほぼ0** | 30秒〜3分 | ★採用 |
| ④ 通知メールを拾う | 中 | 数分〜 | ✕ メール遅延と通知設定に依存 |
| ⑤ /notifications API | 小 | 60秒 | △ 予備。いまのトークンに notifications スコープが無い |

③の根拠は公式ドキュメントの実物：
> Making a conditional request does not count against your primary rate limit
> if a 304 response is returned …

**変化が無い回はレート制限を1も使わない。**「見回りが重い」のは回数ではなく毎回まるごと取ることだった。

Events API は使わない。同じ公式ドキュメントに *event latency can be anywhere from 30s to 6h* とある。
**最悪6時間気づかない**ので「即座に気づく」を満たさない。

## 重さ（実測）

1回 = 条件付きGET 2本（Issue一覧・コメント一覧）。変化が無ければどちらも 304・本文0バイト・約0.3秒。
中に60秒ゲート。新しい常駐もlaunchdも増やしていない（心臓と5分便に1行ずつ相乗り）。

## 工事中に実際に踏んだ穴（全部直してある）

1. **gh が見つからない** … 心臓はPATHを整えずにlaunchdから起動されるので `gh` が見えない。
   → gitの資格情報（`git credential fill`）から取る形にした。これが実機で通った本命の経路。
2. **保存が文字列の n で丸ごと落ちる** … 発車待ちの保存処理が n をそのまま並べ替えていたため、
   n が文字列の項目が1件混じっているだけで TypeError。**スマホの「＋発車待ちに追加」も含め、
   積み込みが全部黙って失敗する状態だった。**→ 数として見るように直した（見張り番とは別の、全体の穴）。
3. **初回だけフラグ方式** … 1回目が例外で落ちた拍子にフラグだけ立ち、
   昔から開いている古いIssueを新着として3本積んだ。→ フラグではなく**時刻の基準線**に変えた。
4. **上限で打ち切った回にETagを保存していた** … 次の回が304になり、**積み残しを二度と見なくなる。**
   これで一度 #431 が消えた。→ 最後まで見きった回だけETagを持つ。
5. **未コミットの変更が消える** … 別セッションのgit操作で相乗り行が2回消えた。
   このリポジトリでは**直したら即コミット**。

## 次の担当へ

- 見張り番が黙って死んでいないかは、吐き出し用のログと状態ファイル（stats）で見る。
  `notModified` が増えていれば、ちゃんと見回っていて何も無い、という意味。
- 「見たページ」を毎回1枚だけ残してある。拾われなかった理由（閉じている／基準線より前）を後から追える。
- **工場がIssueへコメントするときは、本文の先頭に `<!-- tamago-factory -->` を必ず入れる。**
  入れないと見張り番が自分の書き込みを拾って、同じ仕事が無限に増える。
- 見る先を増やすときは、スクリプト冒頭の見張り先リストに足すだけ（1リポジトリ＝条件付きGET2本）。
- **いま遡りは打ち切ってある**（Macのメモリが限界のため）。以後は新着だけを拾う。
  昨日〜今日の積み残しを拾い直したくなったら、状態ファイルの基準線を戻す。
