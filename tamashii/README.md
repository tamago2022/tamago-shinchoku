# 魂（tamashii）— ごきげん補給所の宝箱と人格

> 「基礎AIを自前で作ってはいけない。ごきげん補給所が持つべき資産は
> 『何を出せば、この人が少しごきげんになるか』という選球眼とデータ。モデルは交換部品にする。」
> 「C-3POそのものを作らない。C-3POが来た瞬間に『ごきげん補給所の人格と宝箱』を注入できる状態を作る。」
> — たまごさん 2026-09-24

## これは何か

今まで案内人は、**脳（どのAI会社か）と魂（何を出すか）が1本のコードに混ざっていた**
（`status/_1039/lib/voiceConcierge.ts` は、xAIのWebSocketの話と、どの曲を出すかの話が同居している）。
この形だと、脳を替えるたびに魂を書き写すことになる。写すたびに劣化する。

ここでは魂だけを引き剥がし、**3つの道具（口）**にした。

| 口 | やること |
|---|---|
| `osusume(konomi, kibun, ima_no_tana, hito)` | 曲・動画カードを返す。安心4枚＋冒険1枚 |
| `shiraberu(go)` | 棚・アーティスト・曲を引く |
| `jinkaku()` | 人格と会話の決まりを返す（時刻で案内人／深夜のママ） |

**この3つは、どの脳からも同じ形で呼べる。脳を替えてもここは1バイトも書き換えない。**

## 確かめ方

```bash
python3 tamashii/mon.py
```

これが緑でないものは「できた」と言わない（憲法第6条）。

## 決めてあること

- **うんちくは元データにあるときだけ1行。無ければ `null`（黙る）。** 脳に作らせない。
  口の自己試験が「元データに無いうんちくが付いていないか」を毎回突き合わせる。
- **カードはドア。** 各カードに `door: true` と `path` が付く。「聴け」ではなく「開けてみます？」
- **「この流れで」＝固定／「こちらもどうぞ」＝その人ごとに変える。**
  `hito` を変えたときだけ一番下の1枚が変わることを、自己試験が毎回確かめている。
- **趣味の違う2人**が `konomi` に入ったら、安心4枚は片方が全部さらわない（1周に1人1枚ずつ）。
  両方を同時に満たす1枚（`hashi`）は、**見つからなければ `null`。無理に繋がない。**
- **URLを組み立てない。** 叩いて200を確かめていない住所を渡さないため、カードは `path` だけを持つ。
- **乱数を使っていない。** 同じ入力なら毎回同じ答え。`hito` から作る決まった数（FNV-1a）で
  一番下の1枚だけをずらす。だから「同じ人には同じ、違う人には違う」が再現できる。
- **口の中に鍵・モデル名・AI会社の名前を1バイトも置かない。** 自己試験が見張る。
