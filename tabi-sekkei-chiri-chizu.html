① 地域の階層国連 M49 をそのまま使う

「ラオスはアジアだけど中央アジアじゃない」— これは国連統計部の M49（Standard Country or Area Codes for Statistical Use） がすでに解いています。アジアは5つに割れていて、ラオスは 東南アジア(035)、中央アジアは 5カ国だけ(143)。自作の区分はいりません。

M49 の実際の中身（アジア部分・公式）

  • 001 世界
    • 142 アジア（50）
      • 030 東アジア（7）中国・香港・日本・北朝鮮・韓国・マカオ・モンゴル
      • 035 東南アジア（11）ブルネイ・ミャンマー・カンボジア・インドネシア・ラオス・マレーシア・フィリピン・東ティモール・シンガポール・ベトナム・タイ
      • 034 南アジア（9）アフガニスタン・バングラデシュ・ブータン・スリランカ・インド・イラン・モルディブ・ネパール・パキスタン
      • 143 中央アジア（5だけ）カザフスタン・キルギス・タジキスタン・トルクメニスタン・ウズベキスタン
      • 145 西アジア（18）＝いわゆる中東。トルコ・イスラエル・サウジ・UAE・ジョージア・アルメニア・アゼルバイジャン など
    • 150 ヨーロッパ（51）154 北欧／155 西欧／151 東欧（ロシアはここ）／039 南欧
    • 002 アフリカ（60）015 北アフリカ／011 西／017 中部／014 東／018 南部
    • 019 アメリカ大陸（57）021 北部アメリカ／013 中米／029 カリブ／005 南米
    • 009 オセアニア（29）
    • 010 南極（1）
M49 の注意点（先に知っておくと後で揉めない）
・イランは「南アジア」に入る。中東（西アジア）ではない。
・トルコは「西アジア」。ヨーロッパには入らない。
・ロシアは「東欧」。アジアには入らない。
・M49 に「中東」という枠はない。＝西アジア(145) が事実上それ。
・2021年12月に「先進地域／途上地域」の区分は M49 から削除済み。使わない。

それでも M49 だけでは足りない部分 → Wikivoyage の型を借りる

M49 は「国まで」です。その下（地方・都市・村）と、国境をまたぐ場所（ヒマラヤ、ナイアガラ）の扱いは、Wikivoyage の Geographical hierarchy が20年運用して固めた型がそのまま使えます。

  • 地球
    • 大陸 = M49 の 142 / 150 / 002 / 019 / 009
      • 大陸セクション = M49 のサブ地域（030 / 035 / 034 / 143 / 145 …）
        • 国 = M49 の国コード。この階層は飛ばせない
          • 地方（リージョン）中身が増えるまで作らない＝入れ子は後から
            • 都市・村
              • 地区（巨大都市だけ）
  • 7±2 の法則｜1階層の子は7個前後（5〜9）。10個を超えたら中間階層を挟むタイミング。
  • 意味がない階層は飛ばす｜アンドラに「地方」はいらない。国→都市で直結。
  • 穴を作らない・重ねない｜同じ階層の兄弟は重複禁止。地球上どこでも必ず置き場所がある状態を保つ。
  • はみ出す場所は extra-region 扱い｜ヒマラヤのような国境またぎは階層の外に置き、親は1つだけ表示（パン粉は1本道）。

結論（採る案）

世界 → 大陸（M49マクロ）→ 地域（M49サブ）→ 国（M49国コード）→ 地方（任意）→ 都市/村 → 地区（任意）。区分の出典は M49、階層の運用ルールは Wikivoyage。どちらも自作なし。

出典： UNSD — Standard country or area codes for statistical use (M49) ／ UN M49 全コード一覧（2021年12月時点） ／ Wikivoyage:Geographical hierarchy

② バンバン足しても壊れない器今すぐ全部は作らない。持ち方だけ決める

曲・食べもの・アクティビティが何千件になっても壊れない条件は3つだけです。

1｜場所テーブルは1本。親IDと「パス」を持つ

場所（大陸・地域・国・都市）を種類別に分けず1つのテーブルにして、parentId と path を持たせます。

{ id:"la",        kind:"country", parent:"035", path:"142/035/la",    name:"ラオス" }
{ id:"la-lpq",    kind:"city",    parent:"la",  path:"142/035/la/lpq", name:"ルアンパバーン" }

path が文字列なので、「東南アジアの全部」も「アジアの全部」も前方一致1発で出ます。何階層深くなっても検索が増えません。これが「バンバン足しても壊れない」の中身です。

2｜中身（曲・食・遊び）は種類で分けない

曲テーブル・食べものテーブル…と分けると、種類が増えるたびに構造を壊します。1レコード = 1コンテンツで、type と placeId だけ持たせる形にします。

{ type:"song",     placeId:"la-lpq", ... }
{ type:"food",     placeId:"la-lpq", ... }
{ type:"activity", placeId:"la",     ... }

後から「香り」「音」「本」を足すときも、type を1つ増やすだけ。器はそのまま。

3｜表示するときは階層ごとに切る（全件読み込まない）

1ページで世界の全件を読むと、件数が増えた瞬間に死にます。そのページに必要な path 配下だけを配る。地図ページは「国のIDとリンク先」しか持たない。これで件数がいくら増えても地図ページは太りません。

③-2 推し（1つだけ）案1＋2：事前生成SVG＋素のリンク

やること：ビルド時にSVGを1枚作って、国のパスを <a> で包むだけ

  1. Natural Earth（パブリックドメイン）の国境データを取る
  2. mapshaper 等で簡略化（小国は点にならない程度まで残す）
  3. SVGパスに変換。各 path に id="la"（ISO/M49コード）を付ける
  4. パスを <a href="/asia/035/la"> で包む。これでクリック=ただのリンク
  5. 大陸ごとに切り分けたSVGも同じ手順で用意（アジアだけの図、など）

なぜこれか

  • 追加JS 0 KB・追加リクエスト 0。地図ライブラリを一切読まない。他の9案は全部これより重い。
  • 0円。月額もライセンス費もゼロ。従量課金の事故が原理的に起きない。
  • JSが死んでも動く。ただの <a> なので、スマホの回線が細くても・JSが落ちても飛べる。
  • データが何千件増えても地図は太らない。地図が持つのは国IDとURLだけ。中身は遷移先で読む。
  • 後から5（MapLibre）に載せ替えられる。URLの形（/asia/035/la）を今決めておけば、地図の実装だけ差し替えれば済む。

「重くなるならやめる」の判定ライン：SVG本体の gzip 後サイズを実測し、ページ全体で +100 KB を超えたら簡略化をやり直す。それでも超えるなら大陸別に分割する。分割しても超えるなら地図はやめて、リスト（大陸→地域→国）だけにする。
→ この実測がまだ済んでいません。実装便に渡す最初の1手はこれです。

④ お金で解決できるのか結論：買えるが、買う必要がない

「世界地図から国へ飛ぶ」だけなら、無料で足ります。言い切ります。

  • サクサク買える選択肢は実在する｜simplemaps World HTML5 Map $199（約31,200円）買い切り。1ドメイン永続、オフライン動作、外部サーバーと通信しない。カートに入れて終わり。
  • ライブラリを買うなら｜amCharts 5: Maps $180/席（約28,300円）買い切り。ドリルダウン標準装備。無料版もあるがロゴ表示が条件。
  • 月額が発生するのはタイル地図に行った時だけ｜MapTiler Flex $30/月（約4,700円）／Google Maps Starter $100/月（約15,700円）。これは「村までズームして道を見せる」機能への対価で、国へ飛ぶだけなら払う先がない。
  • 0円で足りる根拠｜国境データ（Natural Earth）はパブリックドメイン、TopoJSON変換版（world-atlas）も無料、Leafletも無料、MapLibreも無料、自前SVGはライブラリすら不要。この用途で有料が必須になる箇所は1つもない。
正直に書いておくこと：Mapbox だけは金額を書けませんでした。公式料金ページが単価と無料枠をJSスライダー内にしか置いておらず、静的テキストから読めません。憶測の数字は書かない方針なので、⑤の調べる候補に回しています。

⑤ 来月Gensparkに投げる候補1件＝1行。何を知りたいか＋なぜ

上の★が付いたものから先に。★は「これが分からないと実装の判断ができない」もの。

  1. ★ 簡略化した世界地図SVG（国境つき）の gzip 後サイズを、簡略化率ごとに実測した事例 なぜ：推し案の採否がこの数字1つで決まる。「+100KB超えたらやめる」の判定ができない
  2. ★ クリック可能な世界地図SVGを実運用しているサイトの、実機スマホ（4G・廉価Android）での表示秒数 なぜ：たまごさんの条件は「スマホで軽いこと」。PCの数字では判定にならない
  3. ★ Mapbox GL JS v3 の Map Loads for Web の無料枠件数と超過単価（公式の確定値） なぜ：今回公式ページから読めなかった唯一の金額。比較表に穴が空いている
  4. ★ 場所データが数千〜数万件ある旅行サイトが、地図SVGを何分割して配信しているか（世界1枚／大陸別／国別） なぜ：「バンバン足す」前提なので、どこで分割すべきかの分岐点を知りたい
  5. M49 と ISO 3166-1 と CLDR の地域区分の差分一覧（どの国がどこで食い違うか） なぜ：将来 i18n や外部データと突き合わせた時に、区分の不一致がバグになる
  6. M49 のサブ地域名の公式日本語訳があるか（総務省統計局・外務省の表記） なぜ：「South-eastern Asia」を「東南アジア」と訳すのは自分の判断になっている。公式訳があるならそれに寄せたい
  7. Wikivoyage 以外で、世界→地域→国→都市の階層を運用している大規模サイトの構造（Atlas Obscura / Lonely Planet / TripAdvisor のURL設計とパン粉） なぜ：URLの形を今決める必要がある。後から変えると全リンクが死ぬ
  8. Protomaps / PMTiles を個人サイトで自前ホストした実例の、月あたり転送量と実費（Cloudflare R2 等） なぜ：将来ズーム機能を付ける時の「0円のままいけるか」の上限を知りたい
  9. SVGの要素数（国境パス数）が何個を超えるとスマホのスクロールが引っかかるか、実測データ なぜ：「数千要素で劣化する」という話は見たが、一次データで確認できていない
  10. 地図から詳細へ飛ぶ時の遷移パターン比較（別ページ遷移／モーダル／部分更新）と、それぞれの体感速度の実測 なぜ：「バーンと飛べる」の実現方法が3通りあり、どれが軽いか分からない
  11. 国境が政治的に争われている地域（台湾・パレスチナ・西サハラ・カシミール等）を、旅行サイトがどう表示しているかの実例 なぜ：世界地図を出す以上は必ず当たる。先に方針を持っておきたい
  12. 1ページに数千件のカードを持つサイトの配信方法（分割読み込み／静的生成の粒度）の最新事例 なぜ：曲・食べもの・アクティビティが増えた後の一覧ページが重くなる問題の答え
  13. mapshaper 以外の国境簡略化ツールと、それぞれの「小国が消えない」限界値 なぜ：シンガポールやモルディブが点にならずに軽くできる上限を知りたい
  14. Natural Earth 以外のパブリックドメイン／CC0 な国境データ（更新頻度と粒度の比較） なぜ：Natural Earth の world-atlas は最終リリースが7年前。新しい国境変更が反映されているか確認が必要
  15. amCharts 5 Maps と simplemaps を実際に買って運用した人の、後悔ポイント なぜ：3万円を払う価値があるかは、公式ページには書いていない
