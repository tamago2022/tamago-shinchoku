## ★★ `claude -p` を工場から呼ぶときは、stdin を必ず閉じる（2026-09-27）

### 何が起きていたか（実測）

`tools/auth_keeper.py` のログ、2026-09-27 07:52〜14:35 の10回：

```
判定を見送りました（混んでいて測れなかった(待ち)）   ×10
```

**混んでいたのではない。**`claude -p` は stdin が開いたままだと、それを
「プロンプトの続きが来る」と見て EOF を待つ。心臓（`tools/heartbeat.sh`）の子として
走る処理の stdin は開いたパイプなので、EOFは永久に来ない。
＝毎回120秒でタイムアウトし、「混んでいる」と書かれていた。
**7時間、ログインの生死を誰も測れていなかった。**

同じ日に、切り離して `stdin=/dev/null` で走らせた 1161番の実測は25秒で返っている。
差は負荷ではなく stdin 1点。

### 決まり

- python から呼ぶなら `subprocess.run(..., stdin=subprocess.DEVNULL)`
- bash から呼ぶなら `claude -p ... </dev/null`
- 長い1本は心臓の子にしない（`start_new_session=True` で切り離す）。
  心臓は再起動のたびに自分のプロセスグループを kill -9 するので、途中で殺される。

### 「測れなかった」を「切れた」と書かない（1161番の決まりは有効）

stdin を閉じても測れない回はある（ロード50超のときは本当に起動しきらない）。
そのときは旗を立てない・`use_token` も外さない。**次の回に送るだけ。**
