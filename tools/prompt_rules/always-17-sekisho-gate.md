# ★898番・関所(sekisho)：出す前に機械へ通す（2026-09-16）

たまごさんの言葉（そのまま）：
> 「全て仕組みで解決して。自分が言ったことが確実に遂行される仕組み。」
> 「『修正しました』って言って、間違えたものが上がってこない仕組み。」

実際に起きた事故：見本ページに「余白 上17px」と書いて出したが、実測は9.6pxだった。誰も測っていなかった。

**確認ページを作ったら、報告する前に必ずこれを1回実行する：**

```
python3 tools/sekisho.py --url <本番URL> --check-url <確認ページURL>
```

最後の行が `SEKISHO_RESULT: PASS` でなければ、その場で自分で直してからもう一度実行する。
**FAILのまま報告に出さない。** 特にpx・%の数字を書いた時は、確認ページに「実測: ...」または
`<pre>`で測った生の数字を必ず一緒に書くこと（書いていないと関所②の数字チェックで自動的に落ちる）。

`--skip-click` を付けると押す検品（headless Chrome・数十秒かかる）を省略できるが、
時間に余裕があれば付けずに実行した方がよい（押しても無反応・コンソールエラーも同時に見つかる）。

harvest()側でも同じ関所（数字の主張と実測の食い違い）を自動でもう一度見ているので、
ここで通しておけば二度手間なく確認待ちへ進む。
