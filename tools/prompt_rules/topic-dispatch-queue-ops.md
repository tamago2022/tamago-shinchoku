# ★queue.jsonの積み方・進捗表の見方（2026-09-10・701番棚卸しで新設）

**背景**：この知識は今まで`README.md`にしか書いておらず、Dispatch（たまごさんと会話するセッション）以外の新規セッションには自動で伝わっていなかった。「毎回守ってほしいこと」の欠けていた最後の2点をここに落とす。

## 1. queue.jsonへの積み方

- 発車待ち・完了控えの正本は`status/queue.json`（＋完了済み控えの`deleted.json`）。手で直接編集せず、既存の道具経由で操作する。
- 新しい依頼を積む・題名を付けるときは、本文をそのまま切り詰めない。**題名は`label`（短い名前）を使う**（`label`が無い時だけ本文1行目から短く作る。旧`text[:400]`/`text[:120]`の切り詰めバグは`status/failures.md` #6で修正済み・再発させない）。
- 優先度は画面表示がA〜E＋F（文字）でも、`queue.json`の`priority`は昔からの数字（1=A〜5=E、6=F＝空き枠）のまま。新しいコードを書くときも数字のまま扱う。
- お金がかかる項目には`costsMoney: true`が自動で立つ（`tools/cost_risk.py`）。`costApproved`が無い間は`auto_launcher.py`が絶対に自動発車しない仕様なので、「発車しない」＝「壊れている」ではなくこの仕様が先に働いている可能性を最初に疑う。
- たまごさんが会話で「◯◯直ってないよ、やり直して」と言った時は、番号を聞き返さず`python3 tools/owner_redo.py --text "<手がかり>" --note "<何が直っていなかったか>"`を使う（`--n`が分かっていればそちらを優先）。1件に絞れない時は候補一覧を出すだけで当てずっぽうに戻さない。同じ番号への`ownerRedoCount`が3に達したら優先度を最優先へ上げ、原因の調べ方・実装方法を変えることを`what`に明記する。

## 2. 進捗表の見方

- 土台は`data.js`（依頼一覧・いま動いているもの・TODAY の正本、手更新）。書き換えたら`git commit`→`git push origin main`で数分後に公開URLへ反映される。
- 子セッションが完了するたびに`harvest()`が`status/dispatch_outbox.jsonl`へ1行追記する（`ts`/`n`/`title`/`ok`/`elapsedMin`/`urls`/`result`）。
- Dispatch（たまごさんとの会話）は会話開始時に`dispatch_outbox.jsonl`の全行と`dispatch_reported.json`の`ns`（報告済み番号）を突き合わせ、`ns`に無い`n`だけをまだ報告していない完了として話す。話し終えたら報告した`n`を`ns`へ追記する。
- `type: "cost_confirm"`の行（`n`が`"<番号>-cost"`という文字列、通常の完了報告の数値`n`とは衝突しない）を見つけたら、`message`をそのままたまごさんに見せ、進捗表の💴マークの「💰OKで発車を許可」ボタンを押してもらう。**会話中の「やってみて」だけでは発車しない**——ボタン操作が必須。
- `type: "owner_redo_escalation"`（`n`が`"<番号>-redo3"`）は、同じ経路で3回やり直しが起きたサイン。次に触る担当は原因の調べ方自体を変える。

## 3. なぜ2つに分けたか

`always`系は毎回全セッションに注入されるコスト。queue.json/進捗表の詳細は、日常の実装作業（コード修正・コンテンツ作成）には不要な知識なので、**Dispatch運用・進捗表・queue周りに触れる作業のときだけ**渡す`topic`ルールにした（`INDEX.json`の`keywords`一致時のみ配布）。
