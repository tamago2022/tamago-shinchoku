## 失敗はその場で記録する（924番・2026-09-17）— 人が後でまとめる形にしない

たまごさんの言葉（そのまま）：
「これもデータだから、記録に残されて、なんなら共有されるべき」
「怒られた・指摘された内容が、その場で記憶ファイルと引き継ぎ書に入るようにする。
人が後でまとめる形だと忙しい日に落ちる」（クロ丸は9/14〜16の44時間、記録が1本も無かった実例）。

**たまごさんから指摘・ダメ出し・修正依頼を受けたら、次に何か他の作業に移る前に、その場で1コマンド：**
```
python3 tools/failures_ledger.py --quick "<何が起きたか・何を指摘されたか>" \
    --root-cause "<分かっていれば原因。無ければ省略可>" --n <関連する号番号>
```
詳細なJSON（`--add-json`）を別ファイルで用意する必要は無い。**1行で今すぐ流す方が、
後でまとめて書こうとして落ちるより確実。** 原因やpreventedBy（再発防止の仕掛け）が
まだ分からなくても、まず記録してから埋めればよい（`status/failures.jsonl`は追記専用、
後から同じidへ`--add-json`で情報を足せる）。

### 引き継ぎ書に自動で入る（新しく人が読む場所を増やさない）

`tools/genzaichi.py`が生成する`status/genzaichi.md`（＝新しい担当が最初に読む現在地1枚）に、
**「## 未解決の失敗（924番・引き継ぎで見落とすな）」節を新設した。** `failures_ledger.list_open()`
（preventedByが揃っていない＝まだ生きている失敗）を件数・再発件数・直近3件で自動表示する。
**この記録を書き加える以外、何もしなくても次の担当の現在地1枚に自動で乗る。**

### 既存の自動記録との住み分け

- 機械が検出した失敗（外部検品3連続FIX・関所3連続FAIL等）は、既存の仕組みが
  `status/failures.md`へ既に自動追記している（`kenpin_gate.py`・`sekisho.py`）。
- 本節は**人（たまごさん）からの直接の指摘**を対象にした入口。両方とも最終的には
  `status/failures.jsonl`（機械可読の正本）へ合流させ、`genzaichi.md`の同じ節に出す。
