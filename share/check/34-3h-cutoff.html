#34 3時間を超えたセッションを自動で切る

2026-09-04 20:58 実装・ローカル自動運転（launchd）に反映済み
見張り番（tools/session_watchdog.py）に、「壁時計で3時間経ったら、作業中でも問答無用でセッションを止める」機能を追加した。今までは「止まって（放置=idle）から3時間」しか検知できず、ずっと動き続けているセッションは何時間でも生き続けていた（＝「3時間で切れという指示文が守られないことがある」の正体）。止める前に、そこまでの成果とURLを引き継ぎ書へ回収し、続きをやる新しいセッションを自動で立てる。

① 何を直したか

session_watchdog.py の判定関数 decide() に、セッション開始からの経過時間（elapsedMin。idleとは無関係）が180分を超えたら "hardcut" を返す分岐を追加。5分おきの見張り番サイクル（com.tamago.machine-status launchd）でこの分岐に当たると、①SIGTERMでそのプロセスを止める→②会話ログとmachine.jsonのURL記録から「そこまでの成果」を引き継ぎ書（Markdown）へ書き出す→③続きをやる新セッションを自動で立ち上げる、という順で動く。Dispatch本体（たまごさんとの会話そのもの）・見回り系・retired登録のセッションは対象外（既存の除外ロジックをそのまま流用）。

② 数字

180分壁時計の強制カット基準（WALLCLOCK_LIMIT_MIN）
4/4単体テスト合格（下表）
0/4本実装直後に生きていたセッションのうち今カット対象のもの（全部2〜5分経過で正常）
テストケース入力期待結果
作業中でも3時間超で切れるか（本題）elapsedMin=190・idle=2分・作業中hardcuthardcut ✓
3時間未満は今まで通り無視されるか（回帰）elapsedMin=170・idle=2分・作業中何もしない「動いている」✓
経過時間が取れない時に従来ロジックが壊れないかelapsedMin=None・idle=20分・質問中resume（従来通り）resume ✓
見回り系・Dispatch本体は3時間超でも対象外か（誤爆防止）elapsedMin=300・見回り系タイトル対象外「見回り系は対象外」✓

④ 前と後

スクリーンショットは今回ありません。理由：見た目のある画面ではなく、5分おきに裏で動く自動運転スクリプト（見張り番）そのものの修正のため。代わりに、直した分岐の前後をコードでそのまま示す（③のコミットリンクと同じ内容）。 
【前】idleが3時間続かないと発火しない（decide()）
    if s["idle"] < STALL_MIN:          # 作業中(15分未満の無反応)なら
        return None, "動いている（%s分）"  # ← ここで即return。何時間動き続けても二度と下に進まない
    ...
    if s["idle"] >= HANDOFF_HOURS * 60:  # 3時間"放置"の判定はここにあるが、上のreturnで永遠に届かない

【後】elapsedMin（壁時計・idle無関係）を最初に見る
    em = s.get("elapsedMin")
    if em is not None and em >= WALLCLOCK_LIMIT_MIN:   # セッション開始から180分経っていたら
        return "hardcut", "壁時計%.1f時間経過（作業中でも強制カット）" % (em / 60)  # 作業中でも即カット
    if s["idle"] < STALL_MIN:
        return None, "動いている（%s分）"
正本：tamago-shinchoku リポジトリ tools/session_watchdog.py（WALLCLOCK_LIMIT_MIN・decide()のhardcut分岐・session_urls()）。実行は5分おきのlaunchd（com.tamago.machine-status）が自動で行うため、この修正を保存した時点で次の周期から効いている。3時間を超えるセッションが今後発生すれば、この機能で自動的に切られ、Dispatchの見張り番ログと留守中の判断待ちへ記録される。
