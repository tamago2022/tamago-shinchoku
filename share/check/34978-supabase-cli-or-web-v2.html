#34978 34978号：鍵のSQLはCLIで流せるか、Web画面だけか

2026-10-12 実装・main合流・本番(GitHub Pages)反映まで実測確認
結論：Supabase CLIでは実行できない。Web画面（Supabase SQL Editor、または Lovable 経由）でしか実行できない。実機で3点確認した：①このPCに supabase CLI 自体が入っていない（command not found）②リポジトリの .env には公開キー（publishable key）しか無く、DB書き込みに要る SERVICE_ROLE_KEY・DBパスワード・ACCESS_TOKEN は一切置かれていない（AI側に接続する鍵が物理的に無い）③正本ドキュメント docs/operations/rls-lockdown.md（非公開リポジトリのためリンクは貼れず、本文へ転記）に『適用できるのは2経路（①Supabase SQL Editorに貼ってRun ②Lovable側で流す）、どちらも店主のログインが要る』と明記されている。

② 数字

0件supabase CLIのインストール有無（command not found）
0件.envにあるDB書き込み用の鍵（SERVICE_ROLE_KEY/DBパスワード/ACCESS_TOKEN）
6件.envにある公開用キーのみ（読み取り専用・書き込み不可）
2経路店主のログインが要る適用手段（SQL Editor／Lovable）

④ 押せるリンク

  • Supabase SQL Editor（店主ログインで開く）https://supabase.com/dashboard/project/eecdooahvromxykbldud/sql/new

⑤ 何をどう確かめたか

確認項目結果
supabase CLIが端末に入っているかcommand not found
.envにSERVICE_ROLE_KEYが存在するか存在しない
.envにDB接続パスワード/ACCESS_TOKENが存在するか存在しない
鍵かけ直しSQL(20260801170000_rls_owner_only_lockdown.sql)はmainに存在するか存在する(migrations配下)
実行対象：docs/operations/rls-lockdown.md『鍵をかけ直す手順』。この判定自体はコード変更を伴わないため、本番画面の見た目は変わらない（画面が変わる仕事ではなく『どちらの手段か』を答える調査）。結論と実測根拠を確認ページとして公開した。
