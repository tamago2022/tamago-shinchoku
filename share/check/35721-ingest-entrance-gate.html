#35721 仕入れの入口に機械チェックを追加

2026-11-21 実装・main合流まで実測確認（1回目の指摘を受けて作り直し）
前回この確認ページには、たまごさんが開けないリンク（joy-relief-stationは非公開リポジトリのため、GitHubのコミット画面は本人が押すと404になる）を貼っていました。今回はそのリンクを削除し、代わりに仕組みの中身と実際に動かした結果を、このページの中にそのまま貼りました。このページを開くだけで全部読めます。

① 何を直したか

ごきげん補給所(joy-relief-station)で、仕入れデータの事故を「送信する直前」に止める仕組みを新しく作りました。これまで仕入れ検品（check-ingest.ts）はCI（GitHub上での事後チェック）には既にありましたが、工場の実際の運用（AIがmainへ直接pushする）では、CIが後から落ちてもpush自体は止まりませんでした。今回、git push の直前に自動でこの検品を走らせ、新しく増えた事故があればpush自体をブロックするようにしました。すでにある古い不具合（直すまで時間がかかるもの）は許容し、新しく増えた事故だけを止めます。

② 数字

5種検品している不具合の種類（×レベル）
4種今は「既存の借金」として許容している種類（IDマップ・動画ID・名カバーの曲名不一致・原曲リンク）
3種許容リストを空にして試した時に「新しい事故」としてpushを止めた種類
今の正常な状態（origin/main）で動かすと exit 0（push継続）。許容リストを一時的に空にして「新しい事故が混ざった」状態を再現すると exit 2（push停止）。下の「⑤実測ログ」に、その場で実際に動かした生の出力をそのまま貼っています。

確認項目結果

許容リストを空にして「新しい事故」を再現した状態で push を試すexit 2（止まる）

対象外の環境（tamago-shinchoku等、check-ingest.tsが無いリポジトリ）何もせず通す（exit 0）

⑤ 実測ログ（たまごさんの手元で再現した生の出力）

origin/main を新しく取り直したクリーンな場所（他の作業の混入なし）で、実際にこのhookを動かして確認しました。

テスト①：今のまま（既存借金のみ）→ exit 0 
$ echo '{"tool_input":{"command":"git push origin main"}}' | node .claude/hooks/pre-push-ingest-check.mjs
（標準出力・標準エラーとも空。終了コード 0 ＝ push はブロックされず続行）
テスト②：許容リストを一時的に空にして「新しい事故」を再現 → exit 2 
仕入れ検品で新しい × が 3 件出たため push をブロックした。（新規: IDマップ、動画ID、名カバーの曲名不一致）

#!/usr/bin/env node
// PreToolUse(Bash): git push の直前に「仕入れ検品」(scripts/check-ingest.ts) を走らせ、
// 既知でない新しい × (error) があれば push をブロックする（35721号）。
//
// 背景：npm run ingest:check / CIの「仕入れ検品」ステップは既に存在するが、この工場の
// 実運用（憲法第四条）はAIセッションがmainへ直接pushする形で、CIが事後に落ちても
// 反映そのものは止まらない。pre-push-typecheck.mjs と同じ「push直前に入口で止める」
// パターンをコピーして、仕入れ検品にも同じ防御を足す。
//
// 既知のエラー（直すまで許容する既存借金）は隣の ingest-check-baseline.txt に
// check名を1行ずつ書く（typecheckのTSコード単位より粗い粒度。check名が一致していれば
// detail内の個別曲が増えても既存借金として許容する。35721号指示どおりのシンプル粒度）。
//
// 依存が無い環境（npx/tsx自体が無い等）や対象外リポジトリ（scripts/check-ingest.tsが
// 無いworktree等）では黒く通す（push を道連れにしない。pre-push-typecheck.mjsと同じ安全策）。
import { readFileSync, existsSync } from "node:fs";
import { execFileSync } from "node:child_process";
import { join, dirname } from "node:path";
import { fileURLToPath } from "node:url";

let input = {};
try { input = JSON.parse(readFileSync(0, "utf8")); } catch { process.exit(0); }
const cmd = String(input?.tool_input?.command ?? "");
if (!/\bgit\b[^;|&]*\bpush\b/.test(cmd)) process.exit(0);

const here = dirname(fileURLToPath(import.meta.url));
// pre-push-typecheck.mjs と同じ補正：`cd /path/to/worktree && ... git push ...` の形で
// 別ディレクトリへ明示的に移動している場合、そこを検査対象にする。
let root = process.env.CLAUDE_PROJECT_DIR || join(here, "..", "..");
const cdMatch = cmd.match(/\bcd\s+("[^"]+"|'[^']+'|\S+)/);
if (cdMatch) {
  const candidate = cdMatch[1].replace(/^['"]|['"]$/g, "");
  if (existsSync(join(candidate, ".git"))) {
    root = candidate;
  }
}

const checkScript = join(root, "scripts", "check-ingest.ts");
const assetStub = join(root, "scripts", "_asset-stub.mjs");
// この仕組みが前提とするファイルが無いリポジトリ（tamago-shinchoku等）やworktreeは対象外。
if (!existsSync(checkScript)) process.exit(0);

// 実運用の joy-relief-station では tsx は npm install では入らず、npx が内部キャッシュ
// (~/.npm/_npx) 経由で解決する（node_modules/.bin/tsx は存在しない）。そのため
// node_modules/.bin/tsx の有無では判定せず、実行を試みて「npx自体が無い(ENOENT)」場合
// だけを依存欠落として黒く通す。これならworktreeでも、一度でもこの機種でtsxが
// 解決できていれば実際にチェックが走る。
const args = existsSync(assetStub)
  ? ["tsx", "--import", "./scripts/_asset-stub.mjs", "scripts/check-ingest.ts"]
  : ["tsx", "scripts/check-ingest.ts"];

let out = "";
try {
  execFileSync("npx", args, { cwd: root, encoding: "utf8", stdio: ["ignore", "pipe", "pipe"], timeout: 150000 });
  process.exit(0); // 問題なし（exit 0 = ×なし）
} catch (e) {
  if (e.code === "ENOENT") process.exit(0); // npx自体が無い環境は道連れにしない
  out = `${e.stdout ?? ""}${e.stderr ?? ""}`;
}

// 「  × チェック名: 詳細...」の行からチェック名だけを拾う（詳細は複数行に渡ることがあるが、
// 新しい × 行は必ず先頭が "  × " で始まる）。
const foundChecks = new Set(
  [...out.matchAll(/^\s*×\s+([^:]+):/gm)].map((m) => m[1].trim())
);

if (foundChecks.size === 0) {
  // × の出力形式を認識できなかった（将来のスクリプト変更やnpxの想定外の失敗）。
  // 何が起きたか判別できない状態でpushを人質にしない（pre-push-typecheck.mjsの
  // 「out.includes('error TS')で判定できない時は通す」と同じ方針）。
  process.exit(0);
}

const baselinePath = join(here, "ingest-check-baseline.txt");
const baseline = new Set(
  existsSync(baselinePath)
    ? readFileSync(baselinePath, "utf8").split("\n").map((l) => l.trim()).filter(Boolean)
    : []
);

const fresh = [...foundChecks].filter((c) => !baseline.has(c));
if (fresh.length === 0) process.exit(0); // 既存借金のみ

process.stderr.write(
  `仕入れ検品で新しい × が ${fresh.length} 件出たため push をブロックした。` +
  `（新規: ${fresh.join("、")}）\n` +
  `直すか、本当に既存借金に追加してよいなら .claude/hooks/ingest-check-baseline.txt に ` +
  `チェック名を1行足してから push すること。\n\n` +
  out.slice(0, 4000) + "\n"
);
process.exit(2);
