#120051 Genspark納品の配管：届いた原稿が人の手なしで本番まで通る

2026-10-18 実装・main合流・本番(GitHub Pages)反映まで実測確認
Genspark が GitHub の Issue に「【納品】」と書くと、工場が原稿を自動で受け取り、仕上げの便を積み、本番に出たら同じ Issue に「公開しました＋URL」を書きます（#1015・#1018 のコメント欄に実物あり。本体リポは非公開のためここからはリンクしません）。今日見つけた穴を4つ埋めました：①緊急の納品便が Fable 便44本に席を取られて3時間発車できなかった→Fable レーンの席を1つ貸す ②GitHub の一覧が取れなかった回に、その間に立った Issue を永久に飛ばしていた→基準線を進めない ③受領コメントが応答待ちで落ちると二度と書かなかった→次の回から書き直す ④仕上げが終わる前に「公開ボタンを押して」と知らせていた→仕事が終わってから知らせる。 ⑤（夜に追加）同じ原稿が2つの Issue（#1018・#1029）から届き、便が3本（120098・122649・122654）立って同じページを別々に仕上げていた→受付係が積む前に「中身（md5）が同じ／同じ号の便が発車待ち／同じ本番URLの便が走行中」を見て、二重には積まず先の便に合わせる（Issue にはその旨を書き、公開したら両方の Issue に本番URLを書く）。
