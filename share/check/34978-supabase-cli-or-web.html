#34978 SupabaseへのSQL適用：CLIか人間のWeb画面か

2026-10-12 実装・main合流・本番(GitHub Pages)反映まで実測確認
結論：AI側はSupabase CLIで本番にSQLを実行できません。人間がWeb画面（Supabase SQL Editor）に貼るか、Lovableのチャット経由で流すしかありません。理由は「権限」ではなく「手元に鍵が無い」ことです。Supabase CLI自体はこのMacで動かせます（npx supabase --version → 2.120.0 で起動成功）。しかし本番につなぐにはSUPABASE_ACCESS_TOKENか、パスワード入りのDB接続文字列、またはSUPABASE_SERVICE_ROLE_KEYのどれかが必要で、そのどれもこの作業環境には置かれていません（.envにあるのは誰でも読み書き制限付きで使える公開キーSUPABASE_PUBLISHABLE_KEYだけ。値は見ずに変数名だけ確認しました）。GitHub Actions側のSecretsにも同じ鍵は登録されていません（過去のセッションがgh secret listで実測済み）。つまりAIは「流す」道具（CLI）は持てても、「鍵」が無いので実行できません。

② 数字

0件AI側で実行できた本番SQL適用（今回・過去とも）
1件現在も本番に未適用のテーブル（henshin_orders）
2通り唯一の実行経路（①店主がSQL Editorへ貼る②Lovableチャットに頼む）

④ 押せるリンク

  • 本番サイト（ごきげん補給所／このRLSロックダウンの対象サイト）https://joy-relief-station.lovable.app/

⑤ 何をどう確かめたか

確認項目結果
Supabase CLIはこのMacで起動できるかできる（npx supabase 2.120.0）
本番DBに接続する鍵（ACCESS_TOKEN／DB接続文字列／SERVICE_ROLE_KEY）がこの環境にあるか無い（.envの変数名を確認。あるのは公開キーのみ）
本番の実データで欠けを見回った結果henshin_ordersテーブルのみ未適用、他8項目は適用済み（node scripts/patrol/check-db-schema.mjs を実行）
実測内容（2026-10-12・このセッションで実際に実行）：①npx supabase --version→起動成功（2.120.0）、CLI自体は動くが本番への接続情報は別問題。②.envの変数名だけをマスクして確認→SUPABASE_URLとSUPABASE_PUBLISHABLE_KEY（公開キー）のみで、書き込み・DDL権限を持つ鍵は無し。③node scripts/patrol/check-db-schema.mjsを実行→公開キーで本番の実データへ接続し、8項目は適用済み・henshin_ordersの1テーブルだけ未適用と判明、スクリプト自身も「AIはSQLを流せません。店主がSupabaseのSQL Editorへ貼る必要があります」と出力。
根拠（リポジトリ内の正本 docs/operations/rls-lockdown.md より転記。このファイルはたまごさんが開けない非公開リポジトリ内にあるため、リンクではなく本文に引用します）：「適用できるのは次の2経路だけで、どちらも店主のログインが要る。1. Supabase の SQL Editor へ貼って実行する　2. Lovable 側で流す。AI側にはDB接続情報もSupabase CLIも無いため、AIはSQLを書くことはできても流すことはできない。」
