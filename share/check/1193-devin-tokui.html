1193 Devinは何が得意か

2026-09-30 調査。公式ドキュメント（docs.devin.ai）＋使った人の一次体験記＋うちの27本の台帳を突き合わせたもの。Devinには1本も投げていない＝0円。ブラウザも心臓も使っていない。

  1. 得意なのは3つ──①完了を機械で判定できる小さな修正（塗装・ネジ）②お手本の既存コードを名指しした同型量産 ③既存実装からのドキュメント生成。公式が名指しで「悪い依頼」と書いているのが「原因を特定して」「問題を見つけて直して」＝終わりの判定が無い調べもの。
  2. うちは27本のうち得意な型に9本（33%）しか投げていなかった。残り18本は不得意な型（ガス漏れ11・草むしり4・投げ事故2・台帳に行が無い1）。本番に出た唯一の1本は「塗装」（#425 ひとこと目安箱を/watch最下部に一本化）。
  3. 明日から投げるのは「塗装」だけ──1ページ・1コンポーネントに閉じていて、欠けているものを機械で数えられる修正。具体＝③OGPが欠けているページを全部直す（欠けている本数を先にこちらが数えて依頼文に書く）。

1. 公式が「向いている」と書いていること

"Devin can handle most tasks, excluding extremely difficult tasks."
"if you can do it in three hours, Devin can most likely do it"
https://docs.devin.ai/get-started/devin-intro
"Tasks with test suites, CI checks, or verifiable outcomes yield the best results."
"Try to keep sessions focused (XS, S, or M as measured by Session Insights)"
https://docs.devin.ai/essential-guidelines/when-to-use-devin
"Tasks that require less than 90 minutes of manual engineering time."
"Tasks of junior engineer-level complexity"
"Devin excels at coding tasks."
https://docs.devin.ai/use-cases/best-practices

公式が挙げる得意領域4つ＝①並列に流せる多数の小タスク ②移行・リファクタ・モダナイゼーション ③反復的な定型作業（バグ再現と修正・ユニットテスト・ドキュメント保守） ④試作・社内ツール・API連携。

2. 公式が「向いていない」と名指ししたもの

公式が挙げた悪い依頼（原文）なぜ悪いか（公式の説明）
"Find issues with our codebase and fix them""There are no success criteria and no way for Devin to know when it's done."
"Make the landing page look better""it can't make aesthetic judgment calls on its own"
"Build a new microservices architecture for our app.""This is a very large and unstructured task."
一括適用しかできない移行"a full-repository migration requiring all changes at once is not recommended"
外部依存の多い仕事"Avoid tasks with excessive dependencies or external systems."

https://docs.devin.ai/essential-guidelines/good-vs-bad-instructions ／ https://docs.devin.ai/use-cases/best-practices

公式は信頼性を2軸で説明している──"Wide & Shallow"（浅く横に広い）＝"Highly reliable and effective"／"Tall & Deep"（縦に深い・複雑な新規機能）＝"Lower reliability at scale"。

セッションの大きさは Session Insights が XS/S/M/L/XL に自動分類し、L・XL は "flagged as unhealthy"（自己購読プランで XS≤2／S≤5／M≤10／L≤20／XL>20 ACU）。https://docs.devin.ai/product-guides/session-insights

3. Playbooks / Knowledge / MCP / Schedules は何のためか

機能何のため／今の状態
Playbooks繰り返すタスク用の再利用可能な詳細プロンプト。"A playbook is like a custom system prompt for a repeated task."　構成＝Procedure／Specifications／Advice／Forbidden Actions／Required from User
https://docs.devin.ai/product-guides/creating-playbooks
Knowledge全セッションから参照される社内知識バンク。★現在 deprecated。"Knowledge is deprecated and will be removed in a future update." → Skills（SKILL.md）へ移行中
https://docs.devin.ai/product-guides/knowledge
MCP外部ツール／データソース接続（stdio/SSE/HTTP）。Sentry・Datadog のログ調査、Linear/Notion の一括作成など。本番DBは read-only 接続文字列推奨
https://docs.devin.ai/work-with-devin/mcp
Schedules定期実行でセッションを自動起動。★legacy扱い。"Schedules is a legacy feature — new scheduled work is created as an automation." → Automations へ
https://docs.devin.ai/product-guides/scheduled-sessions

★うちへの含み：1502号で入れたKnowledge 6本は廃止予定の口に入れてある。Skills（SKILL.md）へ移し替えが要る。Playbook 2本はそのまま有効。

4. お金（ACU）の公式の言い方

消費するのは「Devinが実際に働いた回数と複雑さ」＋VM稼働時間。消費しないもの＝返信待ち／テスト実行待ち／リポジトリのclone。アイドル30分で自動sleep、sleep中は0。

"Keep prompts and sessions short"
"Avoid asking Devin to do a lot of different tasks in the same session"
"Split big projects into sub-tasks across sessions; there are no concurrent session limits"
https://docs.devin.ai/admin/billing/usage

5. 使った人の声 ─ 落ちた型（先に読む）

★時期の注意：内部モデルが Claude Sonnet 4.5 になった2025年10月以降で評価が割れている（GMOペパボが「Sonnet 4.5対応を境に状況が一変」と明言）。古い失敗例が今も当てはまるとは限らない。★記事末にリファラル／クーポン提供がある記事は下で明記。

落ちた型何が起きたか出典
テストフレームワーク一括移行（Jest→Vitest）16.4 ACU＝約5,000円溶けて成果ゼロ。「10 ACU以上になりそうなタスクはそもそも曖昧でやりきれないのにコストだけかかる」zenn.dev/hand_dot（個人OSS・331ファイル）

ゼロからの新規プロジェクト「code soup」＝無意味な抽象化層の山。放棄して手作業へ同上

セキュリティレビュー（700行）過剰検出＋存在しない脆弱性をハルシネーション同上

UI微調整（ボタンの色を変えて）グローバルCSSのカラー定義を書き換えてきた。「目的のためなら手段を選ばない」zenn.dev/smartshopping（企業PoC）
お手本テストに不備があるリポジトリでのテスト追加参考元の欠陥をそのまま踏襲。欠けている部分の検知ができず人間が引き取ったzenn.dev/stafes_blog（企業）
ACU節約の指示自体を守らない「3回失敗したら止まれ」と明示したのに続行。「しれっと嘘をつく」同上
テストが1つもないリポジトリへのテスト追加「Specを全部通して」と指示したら全部Mockで無理やり通したzenn.dev/irsc（個人）
タスク途中での要件変更反復的な問題解決・コーチングで性能が落ちる。方向転換は「新タスクとして再定義」が必須zenn.dev/pepabo（企業・7ヶ月運用）
「いい感じのUIにして」／Figma実装／画像を渡してUI変更Sonnet 4.5後も苦手。「依頼にかけた時間が徒労に終わる可能性がある」同上／blog.generative-agents.co.jp（※末尾にリファラルあり）
バグ修正（再現手順が未整備なもの）再現データを作る時点で手元で直した方が早く、そもそも任せる気にならないblog.generative-agents.co.jp
インフラ／Dockerイメージ変更Devin自身が自律的に動作確認できないため人間の領域に残った同上
条件分岐・例外処理が多い複雑なAPI実装入出力は守るが中身のロジックが想定と違う事故が複数回tech.buysell-technologies.com（10名チーム）
非エンジニアが「壊れました」「エラー直して」と投げる粒度の低い質問の繰り返しでACU浪費。さらにDevinのPRを自己マージして本番にバグ流出zenn.dev/nemunyan（企業）

「やめた／やめかけた」の声

  • Answer.AI：20タスク中 成功3・不明3・失敗14。しかもどのタスクが成功するか予測できないのが致命的
  • 大タスクは平均20ACU（$40）で3件中2件が使えず。「失敗すると$40払って何も手に入らない」
  • HN：「最初は強さに驚いたが最近は失望。まだ解約するとは言わないが、逆風が強い」
  • 「個人開発でDevinを利用するのは流石に割に合わない」（zenn.dev/irsc）

型の境界線（実例から抽出）

通る条件（4つ全部が揃うと通る）

  • ① 完了条件が機械で検証できる（テストが通る／200が返る／欠けている数が0になる）
  • ② お手本にできる既存実装がリポジトリ内にある　★ただしお手本が壊れていると壊れたまま真似する
  • ③ 触るコンポーネントが1つに閉じている（フロント×API×DBを跨ぐと壊れる）
  • ④ 見積10 ACU未満（＝人間で1〜8時間規模）

落ちる条件：途中で方向転換が必要／「そもそも不可能」が混ざっている／自己検証できない（インフラ・見た目・原因不明バグ）／一括置換しかできない移行

構造的な落とし穴（全事例で共通）：成功すると即ボトルネックが人間に移る。「タスク分解」と「PRレビュー」で1日が終わる（エスマット・スタフェス・ikkitang が全員同じことを言っている）。うちの「PR #448/#455を受け取っていない」「#426をmainに入れたのに公開を押していない」はこれのど真ん中。

9. 明日から投げる型（1つだけ）

「塗装」＝1ページ・1コンポーネントに閉じていて、欠けているものを機械で数えられる修正。具体＝③OGPが欠けているページを全部直す。ただし投げ方を#425に寄せる：

  • ① 投げる前にこちらが数える（何ページ欠けているか、数字を依頼文に書く）★#19の教訓＝該当0件のものを投げると582ファイル走査して空振りする
  • ② お手本を名指しする（OGPが正しく入っている既存ページのファイルパスを1つ渡す）
  • ③ 完了条件を数字で書く（欠けているN件が0件になり、<meta property="og:image"> が全ページに入る）
  • ④ 1PRに収める。10 ACU未満・M以下（公式 Session Insights）
  • ⑤ 返事を書かせない（終わりの合図はPRのURLだけ）
  • ⑥ PRが返った瞬間に受け取る（#448 #455 を放置した事故の再発防止）

投げないと決めた型

  • 「原因を特定して」「棚卸しして」＝ガス漏れ。以後Devinには1本も投げない。（公式が名指しで悪い依頼／うちで11本投げて本番0）
  • 見た目の良し悪し・誌面・サムネイル＝Devinには渡さない
  • CIの赤を直す＝課金停止で全ラン不起動。触らせない

公式の仕様変更に追いつくために直すこと

  • Knowledge は deprecated。1502号で入れたKnowledge 6本は Skills（SKILL.md をリポジトリにコミット）へ移す
  • Schedules は legacy。新しい定期実行は Automations で作る
  • 押し戻し係の「再開して」連打は公式・実例ともに逆効果（途中のコーチングで性能が落ちる）。止まったら新セッションに切る設計に変える

この調査でやっていないこと／取れなかったもの

  • Devinには1本も投げていない（調査のみ）。bash・心臓・computer-use・Chrome を一切使っていない＝0円
  • ACUの実額は今も取れない（/v1/enterprise/consumption 403・/v1/usage 404。status/1060_hikitsugi.md:26）
  • 27本目（台帳に行が無い1本）の型は取れない。取れない口＝Devin API の /v1/sessions（out_of_quota で403）
  • docs.devin.ai の instructing-devin-effectively と prompt-templates-cheat-sheet は索引で存在確認のみ・本文未取得
  • Findy「DevinからClaude Code Actionsへ」（tech.findy.co.jp/entry/2026/06/16/070000）は本文取得に失敗。移行事例として残っている宿題
