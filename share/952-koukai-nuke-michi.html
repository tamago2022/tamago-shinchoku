「公開ボタンが押せない」の抜け道を
8つ並べて、1つ選ぶ

コードは直せる。pushもできる。なのに本番に出ない。詰まっているのは1点だけ —— Lovableの公開（Publish）が人の指でしか押せないこと。 ここを人の手なしで押す方法を、机上ではなく公式ドキュメントの実物で確かめて並べた。

結論を先に。 Lovable MCPサーバーの deploy_project が答え。 全プラン（無料を含む）で使える。 そしてクレジットを食わない—— Lovable公式FAQに「クレジットがかかるのは create_project と send_message だけ。 それ以外のツールは無料」と明記されている。deploy_project は「それ以外」側。 つまり「チャットに publish して と頼む」＝クレジットが飛ぶ、を避けたまま、公開だけを押せる。
たまごさんの手は最初の1回、接続の承認だけ。以後はゼロ。

「1ミリも手が要らない手」は、正直に言うと無い

Lovableのアカウントに「これは本人だ」と1回名乗らないと、外から公開は押せない。 それは仕様というより、アカウントというものの定義そのもの。 本当に手0回で済むのは #2（GitHub Pagesへ引っ越す）だけで、その代わり住所が変わる。
だから #1（手1回・住所そのまま）を本命、#2（手0回・住所が変わる）を保険として両方敷く。 #1が通れば #2 は使わなくていい。#1が何らかの理由で通らなくても、#2 が動いていれば本番に出ないという状態は二度と起きない。

#1をどう通すか（たまごさんの手＝「許可」を1回押すだけ）

実測：Claudeのコネクタ一覧にLovableは載っていない（2026-09-19に検索して0件）。 だから「コネクタを探す→Lovable」では出てこない。URLを直接足す形になる。

足すURLはこれ1本 → https://mcp.lovable.dev

  1. Mac側のセッションに1行走らせる。 claude mcp add --transport http lovable "https://mcp.lovable.dev" ——ここまでたまごさんの手は0回。
  2. 最初にLovableのツールを使うとき、ブラウザが開いてLovableのログイン確認が出る。 たまごさんはすでにChromeでLovableにログインしているので、出るのは 「許可」ボタン1つ。これが唯一の1タップ。
  3. 以後ずっと0回。「公開して」と言うだけで本番へ出る。

スマホ／Claudeアプリ側から入れたい場合は、設定 → コネクタ → カスタムコネクタを追加 に 同じURLを貼る形でも同じところに着く。

このページ自体が「手0回の公開」の実物

このページは、セッションがコミットしただけで本番に出ている。 Mac側で30秒おきに回っている常駐が、未pushのコミットを見つけて押し出し、 GitHub Actions が Pages へ配った。途中でたまごさんの手は1回も要っていない。 つまり #2 の道は、理屈ではなく今この瞬間に動いている。 joy-relief-station に同じ pages.yml を1本置けば、同じことがあちらでも起きる。
